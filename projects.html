Carbon: A Self-Hosted Spreadsheet Database

A spreadsheet database that runs on hardware I own rather than rented cloud. Every table a user creates becomes a real CREATE TABLE in PostgreSQL with typed columns, so filtering executes as a WHERE clause inside the database instead of JavaScript sifting rows the browser already downloaded. That one decision is what lets the same interface stay responsive at a hundred rows and at a million. Six Docker services on a single machine, and every table exports whole to CSV, JSON, or Excel.

Objective

Most project tools make the work fit their shape. I wanted one database that could hold a project, a to-do list, and a personal goal side by side, then reorganize as the work changed rather than staying in a fixed layout. Self-hosting answered the second requirement: no per-seat pricing, no vendor able to revise the terms, and no proprietary format standing between me and my own records.

Architecture
  • •A schema engine that compiles interface actions into DDL, so columns and constraints are enforced by PostgreSQL rather than simulated in application code
  • •One Page model underneath tables, dashboards, and notes, so a new view is a presentation choice instead of a separate subsystem
  • •WebSockets over Django Channels pushing row and schema changes to every open session
  • •Celery running imports, exports, and other long jobs with live progress reporting
  • •Invite-only accounts on httpOnly cookie sessions, terminated by Caddy
Engineering practice
  • •Every slice ships as a written plan of test-driven tasks and closes only after manual browser verification
  • •Over 2,300 automated tests across the backend and frontend, run green before any merge
  • •Defects recorded as Symptom, Cause, Fix, and Prevention, so a fix generalizes past the one bug
  • •A numbered work queue whose entry IDs are cited by every plan and log entry
  • •Restores drilled against real backups rather than assumed to work, and a version gate on every push
Outcome
  • •Deployed and running, invite-only while the build continues
  • •Real tables, live sync across open sessions, and dashboards built on the same data
  • •Notes, relations between tables, and an automation engine
  • •Runs on the home infrastructure described below, which is the workload that stack was sized to hold
  • •New work shipping on a regular cadence

Revenue Cycle by Design: A Multi-Facility Modeling

Designed and generated a dataset of 250,000 claims in Python using rule-based operational and financial logic, then normalized the raw output into schemas with Power Query and analyze reimbursement performance, denials, efficiency, and profitability.

Business questions
  • •How are A/R loads and collection rates tracking month over month?
  • •Which payers generate the highest write-off burden per encounter?
  • •Where are denial rates concentrated, by provider, CPT, or payer?
  • •How does reimbursement compare to allowed revenue across encounter types?
Approach
  • •Cleaned and transformed raw billing data using Python and Power Query
  • •MPRR reductions and standardized adjustment coding
  • •Built univariate and multivariate analysis across payer and encounter dimensions
  • •Designed an interactive Excel dashboard with slicers for payer, month, and provider
  • •Produced a comprehensive billing report with provider-level KPIs
Key metrics
  • •Reimbursement totals and reimbursement rate
  • •Denial volume and denial trends
  • •Operational efficiency indicators
  • •Profitability comparison
Outcome

Produced a reporting tool that enables comparison of performance drivers and demonstrates how reimbursement patterns, denials, and operational processes influence financial outcomes.

Facial Emotion Recognition: Deep Learning with Convolutional and Artificial Neural Networks

Built and compared multiple deep learning models to classify facial expressions across four emotion categories. Progressed from a baseline ANN through increasingly refined CNN architectures, achieving 91% accuracy through systematic tuning of dropout layers, training epochs, and preprocessing strategy.

Objective

Develop a computer vision model capable of accurately classifying facial expressions into four emotion categories: happy, sad, surprised, and neutral. Part of a broader direction in affective computing and emotionally intelligent machine behavior.

Approach
  • •Baseline ANN model established as performance reference
  • •Progressively refined CNN architectures across four model iterations
  • •Applied dropout regularization to reduce overfitting
  • •Increased training epochs to improve generalization
  • •Evaluated grayscale vs. RGB input for transfer-learning alignment
Key metrics
  • •Baseline ANN: 56% F1 score (best on surprise)
  • •Model 1 (simple CNN, no dropout): 59% F1
  • •Model 2 (refined CNN): 69% F1
  • •Model 3 (optimized CNN): 91% F1
Outcome

Achieved 91% classification accuracy through iterative model improvement. CNN depth, dropout tuning, and epoch scaling significantly outperformed simpler ANN architectures. Matching input format (grayscale) to model expectations improved alignment and reduced preprocessing artifacts.

Self-Hosted Home Server Infrastructure

Architected and deployed a production-grade self-hosted environment operating under the huy.gg domain, encompassing this website, email infrastructure, and additional public-facing and private services. Built on a fully containerized stack with layered security, encrypted remote access, automated certificate management, and network-level DNS filtering, running continuously as a live, managed production environment.

huy.gg is more than a label and more than a host. It's the synthesized record of how naming, traffic, service exposure, access, identity, and infrastructure are assembled into one operational environment.

Objective

Design and operate a centralized, production-grade self-hosted platform capable of running multiple public-facing and private services under a unified domain, with enterprise-level routing, security, and access control.

Architecture
  • •Docker-based service isolation and orchestration
  • •Nginx reverse proxy with subdomain routing
  • •Cloudflare for DNS, DDoS protection, traffic proxying
  • •Let's Encrypt automated SSL provisioning
  • •WireGuard VPN for encrypted remote access
  • •Pi-hole network-level DNS filtering
  • •MariaDB persistent storage across services
Services
  • •huy.gg: production website & portfolio
  • •Carbon: self-hosted database platform
  • •Self-hosted email infrastructure
  • •ownCloud private file storage & sync
  • •Jellyfin media streaming
  • •Additional containerized services
Outcome

Delivered a fully operational, multi-service production environment running continuously under a live public domain. Demonstrates end-to-end systems thinking across networking, security, containerization, and infrastructure management, well beyond a typical homelab.
