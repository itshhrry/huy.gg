Revenue Cycle by Design: A Multi-Facility Modeling

Designed and generated a dataset of 250,000 claims in Python using rule-based operational and financial logic, then normalized the raw output into schemas with Power Query and analyze reimbursement performance, denials, efficiency, and profitability.

Business questions
  • •How are A/R loads and collection rates tracking month over month?
  • •Which payers generate the highest write-off burden per encounter?
  • •Where are denial rates concentrated, by provider, CPT, or payer?
  • •How does reimbursement compare to allowed revenue across encounter types?
Approach
  • •Cleaned and transformed raw billing data using Python and Power Query
  • •Applied MPRR reductions and standardized adjustment coding
  • •Built univariate and multivariate analysis across payer and encounter dimensions
  • •Designed an interactive Excel dashboard with slicers for payer, month, and provider
What it tracks
  • •Reimbursement totals and rate, denial volume and trend
  • •Operational efficiency and profitability comparison
Outcome

Five facilities modeled across twelve months of 2025. Net collection holds at 82 to 83 percent against a 29 percent contractual adjustment and a 1 percent write-off rate, and a denial traces back to payer, provider, and CPT.

Facial Emotion Recognition: Deep Learning with Convolutional and Artificial Neural Networks

Built and compared multiple deep learning models to classify facial expressions across four emotion categories. Progressed from a baseline ANN through increasingly refined CNN architectures, achieving 91% accuracy through systematic tuning of dropout layers, training epochs, and preprocessing strategy.

Objective

Develop a computer vision model capable of accurately classifying facial expressions into four emotion categories: happy, sad, surprised, and neutral. Part of a broader direction in affective computing and emotionally intelligent machine behavior.

Approach
  • •Baseline ANN model established as performance reference
  • •Progressively refined CNN architectures across four model iterations
  • •Applied dropout regularization to reduce overfitting
  • •Increased training epochs to improve generalization
  • •Evaluated grayscale vs. RGB input for transfer-learning alignment
Key metrics
  • •Baseline ANN: 56% F1 score (best on surprise)
  • •Model 1 (simple CNN, no dropout): 59% F1
  • •Model 2 (refined CNN): 69% F1
  • •Model 3 (optimized CNN): 91% F1
Outcome

Achieved 91% classification accuracy through iterative model improvement. CNN depth, dropout tuning, and epoch scaling significantly outperformed simpler ANN architectures. Matching input format (grayscale) to model expectations improved alignment and reduced preprocessing artifacts.

Carbon: A Self-Hosted Spreadsheet Database

A spreadsheet database that runs on hardware I own rather than rented infrastructure. Every table is a real CREATE TABLE in PostgreSQL with typed columns, so a filter runs as a WHERE clause inside the database instead of JavaScript sifting rows the browser already downloaded. Data arrives as CSV, JSON, or Excel and leaves the same way, whole.

Objective

One database holding a project, a to-do list, and a goal side by side, reorganizing as the work changes. Self-hosted, so there is no per-seat pricing and no proprietary format between me and my records.

Architecture
  • •Types and constraints enforced by Postgres, not simulated in app code
  • •One Page model under tables, dashboards, and notes, so a new view is a presentation choice
  • •Row and schema changes broadcast to every open session
  • •Imports and exports run on a background queue with live progress
Engineering practice
  • •Every slice ships as a written plan of test-driven tasks, closed only after browser verification
  • •Over 2,300 automated tests, green before any merge
  • •Defects recorded as Symptom, Cause, Fix, Prevention, so a fix generalizes past the one bug
  • •Restores drilled against real backups
Outcome
  • •Deployed and running, invite-only while the build continues
  • •Real tables, live sync across sessions, and dashboards on the same data
  • •Notes, table relations, and an automation engine

codemap

A code index that answers questions about a repository without reading it. Built after the tool I was using kept returning the entire neighborhood around whatever I asked about, which is the opposite of an answer.

Objective

Answer where a function lives, what calls it, and what breaks if it changes, across a whole repository, without opening files and without a language model in the loop.

Architecture
  • •Abstract syntax tree parsing into a SQLite database with a full-text search index
  • •Python through the standard library, TypeScript and Vue through the TypeScript compiler, Rust through Tree-sitter
  • •Results ranked by name match rather than expanding outward through the graph
  • •Every relationship carries whether it was proven by an import or inferred from a name
Outcome

Indexed against carbon at 6,050 symbols and 11,609 relationships, which is 69 percent of everything the extractor emitted. Each one records whether it was proven by an import or inferred from a name. Asking what calls one function returns one line.

Why it matters

Search tells you where a name appears. This tells you what depends on it, which is the question you actually have before changing anything.

Self-Hosted Home Server Infrastructure

Private file storage, media streaming, and carbon all run on hardware in my apartment, under one domain. Containerized behind a reverse proxy, with automated certificates, VPN-only access to anything private, and DNS filtering at the network level.

Objective

Run several public and private services under one domain, with real routing, TLS, and access control rather than a flat homelab.

Architecture
  • •Docker containers behind an Nginx reverse proxy, routed by subdomain
  • •Cloudflare DNS and proxying, Let's Encrypt certificates renewing unattended
  • •WireGuard for remote access, Pi-hole filtering DNS network-wide
  • •MariaDB backing the services that need persistence
Services
  • •huy.gg: production website & portfolio
  • •Carbon: self-hosted database platform
  • •Storage and media: ownCloud and Jellyfin
Outcome

Running continuously. Carbon, ownCloud, Jellyfin, and Pi-hole are all served off it, certificates renew unattended, and private services are reachable only over WireGuard.
